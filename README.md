# AI 面试助手

上传一份简历，由大模型解析出候选人画像，然后基于这份简历进行一场追问式的模拟面试，最后出一份**有证据支撑、不吹捧**的评分报告。

面向本地运行的单用户使用，数据不出本机。

---

## 快速开始

```bash
npm install
npm run dev
```

打开 http://localhost:5173 。第一次用需要先去 **设置** 页配好模型。

生产模式（单端口托管前后端）：

```bash
npm run build
npm start        # http://127.0.0.1:3001
```

---

## 配置模型

所有模型都走 OpenAI 兼容协议，在 **设置** 页配置，**不需要改配置文件或重启**。

### 本地 Ollama

```bash
ollama serve
ollama pull qwen2.5:7b
```

设置页选「本地 Ollama」→ 测试连接 → 从模型列表里选一个 → 保存。

本地模型免费且不联网，但追问深度受模型能力限制。7B 级别的模型能跑通全流程，但对提示词的遵循度不如云端模型（本项目已对常见的不听话行为做了应用层兜底，见下文）。

### 云端 API（以 DeepSeek 为例）

设置页选「DeepSeek」→ 填入 API Key → 测试连接 → 保存。

内置预设：DeepSeek、通义千问、Kimi、智谱 GLM。其他服务选「自定义」，手填 baseUrl 与模型名。

**关于 Key 的存储**：API Key 以明文存放在本机 `data/app.db` 里。这是本地单用户应用换取「界面上随时改配置」的取舍。接口从不下发明文 Key，只回掩码（`sk-****1234`），带 Key 的请求全部由服务端发出。如果这个取舍你不接受，可以改用环境变量注入（需自行改 `services/llmConfig.ts`）。

## 语音作答

**按住空格说话，松开结束。** 界面上也有一个「按住说话」按钮供鼠标/触屏使用。

- 基于浏览器原生 Web Speech API，**需要 Chrome 或 Edge**，Firefox 不支持（会降级为纯键盘作答）。
- Chrome 是把音频送到云端识别的，**必须联网**。
- 在输入框里打字时，空格就是普通空格，不会被语音功能抢走。
- 按住期间按 `Esc` 取消本次识别。
- 识别结果会先落到输入框，你可以改错别字再发送。

## 功能

| 功能 | 说明 |
|---|---|
| 简历解析 | 仅支持 PDF（需可复制文字）。提取目标岗位、项目、工作经历、技术栈、年限、自评等 |
| 五档难度 | 实习生 / 初级 / 中级 / 高级 / 行业专家·产品架构师，各档的提问深度与追问力度不同 |
| 预制面试官 | 字节、阿里、百度、拼多多、华为五家大厂风格，按公开面经整理 |
| 自定义面试官 | 可改提示词，改动只影响本次面试；也可另存为常用面试官 |
| 追问式面试 | 基于简历画像逐层追问，并追踪考察覆盖度 |
| 评分报告 | 百分制 + 推荐结论，逐条引用你的原话作为依据 |

## 关于评分：这个工具不会夸你

这是本项目的核心取向。默认模型倾向于给「还行」的中间分和「整体表现一般」这类和事佬评价，那样报告就没有价值了。因此：

- 报告提示词里写死了 11 条评分铁律：宁可偏低、不因态度加分、每个判断必须引用原话、**没有内容的回答（「记不太清了」「不是我负责的」）直接给 0–30 分**、禁止鼓励性套话、禁止和稀泥表述。
- 总分取各维度加权平均，结论由总分推导——避免出现「45 分但结论推荐」这种自相矛盾。
- 没有证据支撑的「优点」会被直接丢弃，宁可优点栏空着。
- 报告页也没有任何庆祝式视觉。

**警告**：报告会相当直接。这是设计意图，不是 bug。

评分维度与权重：项目回答 25%、基础知识 20%、解决问题能力 20%、知识深度 15%、知识广度 10%、语言表达能力 10%。L5 档额外增加「产品与行业思考」「行业沉淀与影响力」两维。

## 模型不听话时的兜底

本地小模型不会老老实实遵守提示词。与其反复加约束，本项目在应用层做了确定性兜底：

| 问题 | 处理 |
|---|---|
| 一次问好几个问题 | `replyCleanup.ts` 只保留第一个问句 |
| 输出 HTML 注释 / 半截进度标记 | 同上去除，避免泄漏到对话界面 |
| 考察要点换词重述、重复 | `textMatch.ts` 用中文二元组重合度去重 |
| 优点条目没有证据 | 直接丢弃 |
| 简历问题与面试问题重复 | 两个字段互相去重 |
| 报告 JSON 格式错误 | 抓 `{...}` 块 + 重试一次 |

覆盖度判定也**不依赖模型输出标记**（实测千问 7B 做不到稳定输出），改由应用层拿问题文本与考察要点做匹配。

## 目录结构

```
apps/server/           Fastify + node:sqlite
  src/db/              表结构、连接、内置数据
  src/llm/             供应商适配、预设、提示词、难度定义
  src/services/        简历解析、面试引擎、评分、文本匹配
  src/routes/          HTTP 接口
apps/web/              React + Vite + Tailwind
  src/pages/           上传 / 配置 / 面试 / 报告 / 设置
  src/hooks/           语音识别、按住说话
  src/components/      评分图、画像展示、基础组件
data/                  运行时生成：app.db、uploads/
requirements/          需求说明与任务列表
scripts/               测试简历生成、端到端验证
```

## 验证

```bash
node scripts/make-test-resume.mjs /tmp/test-resume.pdf   # 生成测试简历
npm run dev
node scripts/e2e-test.mjs                                # 跑完整流程并断言评分不迎合
```

端到端脚本会用故意敷衍的回答跑完 4 轮面试，然后检查报告是否给出低分、是否引用了原话、是否出现鼓励性套话。

## 已知限制

- 简历只支持 PDF，扫描件（图片型）无法提取文字，会明确报错。
- 语音识别依赖 Chrome/Edge 且需要联网。
- 面试官不做 TTS，只输出文字。
- 没有账号体系，单人单机使用。
